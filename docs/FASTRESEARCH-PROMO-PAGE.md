# FastResearch 宣传页设计与实施约束

## 目标与边界

这是一个面向课题组成员、研究者和实验室管理员的产品介绍页。访客应在首屏理解 FastResearch 如何把前沿追踪、文献研读和学术写作串成有序的研究工序，并能一键进入现有工作台。

- 宣传页是独立的介绍入口，不替代工作台，也不改变工作台已有的认证、任务和滚轮交互。
- 根地址 `/` 默认跳转至同源 `/intro`，现有工作台位于 `/workspace`。所有“进入工作台”按钮指向 `/workspace`；部署在子路径时使用应用配置的 base path，不能写死域名。旧 FastCAS 回跳参数和工作台锚点需从根地址转入工作台，避免认证中断。
- FastNews、FastRead、FastWrite 始终按此顺序出现。FastInsight 是学术文献信箱，团队进度是工作台视图；FastTask 和 FastCAS 属于按部署配置启用的集成能力，不与三大模块混为一谈。
- 页面只展示可由当前产品支撑的行为。不得宣称自动生成论文、自动审稿、保证研究成果、全平台实时同步、无条件单点登录或已经拥有尚未接通的数据源。
- 本文记录宣传页方案与实施约束；以当前 [App2.tsx](../src/App2.tsx)、[i18n.ts](../src/i18n.ts) 和 [前端风格.txt](../前端风格.txt) 为事实及品牌基线。

## 创意方向

借鉴 Claude 官网常见的宽松留白、编辑式叙事、克制的排版层级和温和的细节反馈，但不复刻其字体、插画、品牌色、版式细节或文案。FastResearch 应继续以蓝色为识别色；宣传页比工作台更有呼吸感，仍保持学术工具的可信与清晰。

核心视觉概念是“研究从线索走向论证”。一条细线从前沿信号出发，依次经过论文、批注和稿件，最终落入工作台中的工序记录。它可作为段落间的轻量连续元素，不占据正文阅读空间，也不做滚轮劫持。

### 视觉约束

| 项目 | 约束 |
| --- | --- |
| 背景与文字 | 大面积采用偏冷的近白 `#f6f6f9`、白色 `#fff` 与深色 `#101820`；正文 `#475467`。避免整页蓝底或纯白无层次。 |
| 品牌蓝 | 主蓝 `#2f8af5`、深蓝 `#004ab2`、浅蓝 `#e8f3ff`。蓝色只用于品牌、链接、关键数字、焦点和主 CTA。 |
| 辅助色 | 可使用极少量青灰、柔和绿色表示完成状态；不可引入紫色大渐变、橙色主 CTA 或装饰性光球。 |
| 字体 | 中文使用现有系统中文无衬线栈；英文标题可选择许可清晰的人文无衬线字体，但必须有系统字体回退。英中混排不得因字体加载造成明显跳动。 |
| 标题 | 首屏 H1 桌面 56-72px、移动 34-42px；区块标题桌面 36-48px、移动 28-34px；正文桌面 16-18px、移动 15-16px。字距保持自然，不用负字距。 |
| 内容宽度 | 导航与主内容最大宽度 1280px；长文案正文最大宽度 680px；模块展示可扩至 1120px。 |
| 表面 | 以整幅内容带、细分隔线和局部实物截图建立层级。重复模块项可以使用半透明浅底或 1px 边框，圆角不超过 8px；不在卡片里套卡片。 |
| 图像 | 首屏主图必须来自实际工作台的清晰截图或经脱敏的真实产品合成图，能看到工序、信箱或任务状态。不得使用假数据伪装真实用户成果；不可用模糊、过暗或纯氛围图替代产品。 |

### 首屏构图

- 桌面端以实际工作台画面作为宽幅 Hero 背景，标题直接叠放在有足够对比度的留白区域；不要做左右“文案卡片 + 图片卡片”的分栏 Hero。
- H1 以产品名或直白品类为主，例如“FastResearch：让研究的每一步都有来处”。价值说明放在 1-2 句副文案中。
- 首屏主要 CTA 为“进入研究工作台”，次要锚点为“了解研究流程”。两者必须一眼可区分。
- 1440×900、390×844 和 320×700 视口都应在首屏底部露出下一段内容的线索。不要让首屏高度完全吞掉下一节。
- 产品截图使用脱敏、授权的数据。若尚无可靠真实截图，先用可验证的演示工作流截图，并明确标注“界面示意”，不编造论文数量、团队成员或性能指标。

| 顺序 | 区块 | 要传达的事实与推荐文案 | 视觉 / 行为 |
| --- | --- | --- | --- |
| 1 | 导航 | 品牌 FastResearch；锚点“研究流程 / 三个工具 / 文献信箱 / 团队协作”；右侧“进入工作台”和语言切换。 | 桌面 72-80px，滚动后用浅底和细边框固定；移动端保留品牌、语言、菜单及主 CTA，不横向溢出。 |
| 2 | Hero | H1：“FastResearch：让研究的每一步都有来处”。副文案：“从领域新动向，到核心文献，再到论文草稿。FastResearch 把分散的研究任务放进一条可追踪的工作流。” | 清晰工作台实景；两个 CTA；下面可见下一节标题。 |
| 3 | 研究流程 | 标题：“从线索到论证，沿着一条清晰的路径前进”。三步为“发现值得追踪的方向 / 精读需要引用的文献 / 写出有依据的论证”。说明每步有当前任务、状态与下一步，不暗示工具会替研究者自动完成判断。 | 横向三段时间轴，移动端竖排；当前阶段由蓝线连接；滚动进入时逐项淡入。 |
| 4 | FastNews | 标题：“FastNews，让新问题浮出水面”。正文：“围绕你关注的领域追踪新论文、会议动态和研究信号，先发现值得跟进的工作，再决定读什么。” | 实际模块画面或脱敏截图；显示论文/方向示例；“在工作台查看”进入 `/workspace`。 |
| 5 | FastRead | 标题：“FastRead，把读过的内容变成可回查的依据”。正文：“把核心论文和阅读笔记放在同一条研读脉络中，记录来源与观点，写作时更容易回到原文。” | 示意一篇论文与笔记、出处的关联；避免展示并不存在的自动引文功能。 |
| 6 | FastWrite | 标题：“FastWrite，让草稿围绕问题持续生长”。正文：“按研究问题组织章节、论证与实验记录，让分散的素材逐步形成可复核的稿件。” | 展示真实写作工作区；不出现“输入题目一键生成论文”之类承诺。 |
| 7 | FastInsight 信箱 | 标题：“重要的论文，进入你的研究信箱”。正文：“FastInsight 分拣接入来源推送的论文摘要与趋势信息，按个人 Key 进入对应信箱，阅读原文并标记已读。” | 展示列表与论文详情；说明需要已配置推送和个人 Key，空信箱也有真实状态。 |
| 8 | 团队进度与任务 | 标题：“每个人的工序，都在同一张进度图里”。正文：“工作台呈现成员当前工序与完成进度；已接入 FastTask 的部署还可接收分配的任务流水线。” | 使用脱敏的进度图；FastTask 只作为“可选集成”标注，不能写为默认具备。 |
| 9 | 访问与收尾 | “用个人 Key 进入自己的研究空间”；可选说明 FastCAS 在已配置环境下提供登录入口。结尾 CTA：“从下一步研究开始”，按钮“进入研究工作台”。 | 清晰重申进入路径；页脚包含产品名、工作台入口、语言切换及必要链接。 |

模块详情区不能只列三个口号。每个模块至少包含：研究场景、当前可执行动作、产出或记录、与下一工序的关系，以及一个真实界面视觉证据。三段详情的宽度和视觉权重一致，顺序固定为 FastNews → FastRead → FastWrite。模块 CTA 一律进入 `/workspace`，由现有工作台处理个人 Key 验证和对应模块打开逻辑；宣传页不直接拼接外部模块地址或认证 token。

### 模块内容细则

| 模块 | 用户带着什么进入 | 页面应具体解释什么 | 可展示的结果与下一步 | 发布前核验 |
| --- | --- | --- | --- | --- |
| FastNews | 研究方向、关心的主题或待跟进的问题。 | 浏览该方向的新论文、预印本及会议相关动态；从信息流里挑出值得继续阅读的工作。文案重点是“发现与筛选”，不把信息抓取等同于学术判断。 | 被选中的论文和研究线索，顺势进入 FastRead 精读。画面呈现标题、来源、发布时间和主题线索。 | 外部 FastNews 实例实际支持的来源、筛选与保存方式；未经核验不写“覆盖所有顶会”或“实时收录”。 |
| FastRead | 从 FastNews 或其他渠道选定的核心论文。 | 集中阅读与检索文献，留存批注或研读笔记，并让观点能回到论文原文和来源。文案突出“理解、记录、回查”。 | 一组可回查的文献脉络与研读记录，为 FastWrite 的论证提供材料。画面呈现文献内容、笔记和来源关系。 | 外部 FastRead 实例实际具备的批注、检索与导出能力；未经核验不演示自动引文、全文解析或跨库同步。 |
| FastWrite | 研究问题、章节大纲、读过的文献与实验记录。 | 在写作工作区组织章节、草稿和推理论证，逐步形成论文或报告内容。文案强调研究者主导写作与修改。 | 可继续打磨的稿件及阶段性写作成果；完成当前工序后由工作台推进流程。画面呈现结构清楚的编辑区和草稿状态。 | 外部 FastWrite 实例实际具备的版本、协作与引用能力；未经核验不写“一键成稿”“自动投稿”或“自动查重”。 |

FastInsight 需单独说明：它是接收已接入来源推送的论文卡片的信箱，而不是 FastNews 的别名。工作台当前可显示标题、方向、作者、会议/期刊、摘要、趋势信息、原文链接和已读状态；实际字段随推送内容而变。个人 Key 未验证时只展示锁定说明，不能在宣传页展示真实私人信箱内容。团队进度当前展示成员、工序状态和完成比例，未认证或无任务时必须使用真实空状态；FastTask 下发仅在部署已配置集成时描述为可用。

## 交互与动效

- 页面遵循普通浏览器滚动，不使用全屏滚轮翻页或 scroll-snap 强制定位；工作台原有三页滚轮行为仅存在于工作台内。
- 首屏只允许一条轻量的研究路径线和产品画面局部动效。路径线可在首次进入时 600-900ms 绘出；主图无需持续漂浮。
- 区块进入视口时采用 12-24px 位移加透明度变化，持续 350-550ms。每段最多一次，不因反复滚动重复闪动。
- 模块切换如采用标签或轮播，必须同时支持点击、键盘和触屏；不能依赖自动轮播完成信息传达。默认选中 FastNews，顺序始终一致。
- Hover 只改变颜色、边框或轻微阴影，不改变组件占位尺寸。按钮点击反馈不引发布局位移。
- `prefers-reduced-motion: reduce` 时停用路径绘制和进入动效，内容立即可见；所有锚点保持可用。
- 外链或进入工作台的 CTA 有清晰文字与焦点态。点击后在同一标签页进入 `/workspace`，不预先弹出 Key 对话框；由现有工作台根据用户操作处理认证。

## i18n 与内容维护

现有工作台语言状态由 `fastresearch-locale` 保存，支持 `zh-CN` 和 `en-US`。宣传页应读取同一设置并复用 `createTranslator` / `saveLocale` 的语义，语言切换后当前页立即更新；从宣传页进入工作台时保持所选语言。不把宣传页文案写死在组件或 CSS 中。

新增内容统一使用 `promo.*` 命名空间。建议最小键集合如下；实际实现时中英文键必须一一对应，缺键检查应纳入构建或测试。

约束：

1. `FastResearch`、`FastNews`、`FastRead`、`FastWrite`、`FastInsight`、`FastTask`、`FastCAS` 保留品牌拼写，不翻译产品名。
2. 文案变量使用现有 `{{name}}` 形式；中英文变量集合相同。不得在翻译字符串里嵌入 HTML。
3. 标题、按钮、图片替代文本、菜单可访问名称、空状态与错误提示均纳入字典。装饰性图像使用空替代文本，信息性截图写出画面所表达的工作状态。
4. 中英文按钮预留至少 30% 宽度差；长英文单词和中文标题在 320px 宽度可自然换行，不能被按钮或图片遮挡。
5. 内容修改只改字典或相应内容配置；禁止把具体论文数量、客户评价或性能指标写进静态文案，除非已有可复核来源及更新机制。

## 布局、可访问性与性能验收

- 响应式至少核对 320px、390px、768px、1024px、1440px；所有宽度无横向滚动，导航不遮挡锚点标题，主 CTA 始终可见且可点击。
- 图片采用明确宽高或 `aspect-ratio`，防止加载后版面跳动。首屏图优先提供 AVIF/WebP 与合适的移动端裁切；正文后续图片延迟加载。画面必须看得清功能，不靠低对比度或模糊制造气氛。
- 正文与背景满足 WCAG AA，对比度至少 4.5:1；大字至少 3:1。所有可交互项有明显键盘焦点，触摸目标建议不少于 44×44px。
- 一个页面只保留一个 H1。导航锚点与章节标题层级连续；页脚链接有可读名称。产品截图若包含文字，仍需在附近提供可访问的文字说明。
- 不引入无必要的动画库或大型依赖。目标是首屏尽快显示可读标题和 CTA，图片加载失败时文字及跳转仍完整可用。
- 宣传页不请求个人 Key、管理员凭证或团队私有数据；所有截图和示例数据先脱敏。不得在前端静态资源中包含真实 token、Key、论文订阅或成员姓名。
- 浏览器回归至少覆盖：中英切换及刷新保持、所有导航锚点、全部“进入工作台”按钮、移动菜单、减少动效模式、图片失败回退、工作台现有功能与入口未回归。

## 实施顺序与交付判定

1. 确认用于展示的真实工作台截图与可公开的演示内容，并完成脱敏。
2. 建立根地址到 `/intro` 的默认跳转，以及 `/intro` 到 `/workspace` 的同源跳转；验证开发和生产环境的直接访问与刷新。
3. 先完成静态分区、中文文案与中英字典，再加入图片和轻量动效。
4. 完成响应式、键盘、减少动效、页面性能与跨语言视觉检查。

交付时，访客应能在 5 秒内说出 FastResearch 是做什么的；能看懂三个模块的顺序及各自产出；知道信箱与团队进度需要进入工作台使用；从任一 CTA 一次点击即可到达当前工作台。工作台原有流程、认证与三页切换行为保持不变。
